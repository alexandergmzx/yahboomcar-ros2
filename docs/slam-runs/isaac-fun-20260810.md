## What actually happened (narrative)

Alex reported the fun-mode Isaac map "messy, not respecting the movement". The
2026-08-09 session logs were still on disk and already showed the render-pacing
runaway (never previously diagnosed) stacked on the known-OPEN encoder yaw lie.
Tonight: built and negative-controlled the SLAM lens first, then reproduced the
smear under a bounded patrol with the bag rolling, then attributed offline.

Surprises, kept per the evidence-style rules:

1. The duplicate-scan prediction was WRONG (0/3330 vs predicted ~70–75%) — the
   RTX pipeline re-assembles fresh-looking revolutions from an un-re-rendered
   world, so bit-hashing cannot see render-pacing staleness; only time-offset
   fitting can. The lens's stale-scan tile is therefore Isaac-blind as built
   (fine on 2D, where duplicates are the failure mode it was tested against).
2. `slam_preflight`'s 0.00% on a healthy-TF session — the immediate-lookup
   bias above. Two instruments asked different questions and BOTH were right;
   the report's job is to say which question the message filter actually asks.
3. The governor's stale-scan stop never fired this session (patrol never
   starved /scan) — one fewer confound than the 2026-08-10 fun+patrol chaos
   session.
